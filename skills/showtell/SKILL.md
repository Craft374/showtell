# Showtell — Don't just tell. Show it.

정보를 예쁘게 정리하는 게 아니라 **보면서 이해되는 장면**을 만든다. 너는 장면 명세(JSON)만 쓰고, 디자인·움직임·HTML은 렌더러가 만든다.

## 1. 쓸지 말지 먼저 판단한다

다음 중 하나라도 해당하고, 답이 몇 문장으로 끝나지 않을 때 사용한다.

- 두 개 이상의 선택지·설정값을 비교한다
- 원인-결과, 구성 요소 사이의 관계를 설명한다
- 순서가 있는 절차나 작업 흐름을 설명한다
- 수치·데이터의 분포나 변화를 보여 준다
- 복잡한 구조·시스템을 한눈에 보여 준다
- 사진·기록을 근거로 무엇이 잘됐고 잘못됐는지 보여 준다
- 사용자가 나중에 참고하거나 그대로 실행할 문서를 만든다

해당하지 않으면 평소처럼 텍스트로 답한다. 시각화 자체가 목적이 아니다.

## 2. 원칙

장면마다 먼저 묻는다. **"보는 사람이 무엇이 바뀌는 걸 봐야 이해하는가?"** 답이 없으면 그 장면은 정적이고, 그게 맞는 결과다.

v1처럼 "제목 + 표 + 카드 + 사진 + 메모"를 장면마다 쌓으면 PDF를 옮긴 문서가 된다. 그렇게 만들지 않는다.

## 3. 작업 순서

1. **사실 목록부터 만든다.** 머릿속 목록이고, 출력하지 않는다.
   - 모든 숫자를 단위·조건과 함께 적는다.
   - 모든 주장은 불확실성 표시와 함께 적는다.
   - 모든 사진은 캡션에 적힌 메타데이터(모드·셔터·ISO·보정·초점거리)와 함께 적는다.
   - 모든 개수에는 성격을 표시한다: 전체 / 부분(합이 전체) / 하위집합(무엇의) / 다른 것과 겹쳐 셀 수 없는 개수. 예: S 409장과 1/160 419장은 서로 다른 기준이다. 상위 8개 값 목록은 전체가 아니다.
   - 이 목록이 충실성 계약이다. `say`·라벨·값은 전부 여기서만 가져온다.
2. **주인공을 찾는다.** 여러 장면에 반복해서 나오는 대상(사진 601장, 62초 영상)이 있으면 무대 하나로 만들고, 다음 장면에서 `{"continue": "<무대 id>", "states": [...]}`로 이어 쓴다. 같은 대상을 장면마다 새로 그리지 않는다. 이어 쓰기는 바로 앞 장면의 단계형 무대만 가능하다.
3. **장면마다 무대를 고른다. 내용 종류가 아니라 데이터 모양으로 고른다.**
   - **셀 수 있는 대상(1500개 이하)이 속성별로 나뉨 → `units`**
     - 전체 → 분할 → 세분(`of`, 원문이 포함 관계를 말할 때만) → 합치기(`from`) → 강조 순서로 쓴다.
     - 관계없는 기준으로 다시 세면 렌더러가 디졸브한다(점이 이동하지 않음).
   - **값·범위가 눈금 위에 있음(설정값, EXIF, 오늘 vs 내일) → `dials`**
     - 사진을 캡션의 값 위치에 꽂는다.
     - 오늘의 퍼짐은 범위로 그리고, `set`으로 그 범위를 내일 값으로 줄인다.
     - 원문의 대응표(초점거리 → F값)는 `slider`로 만든다.
   - **순서 있는 구간 위의 값(시간 구간, 순서형 값) → `track`**
     - 막대는 0부터 시작하고, 점은 선으로 잇지 않는다.
     - 정확히 읽게 하려면 `scrub`을 켠다.
   - **같은 항목을 여러 경우(상황, 슬롯, 오늘/내일)로 비교 → `lookup`**
     - 의미 있는 `base`를 고른다(실제 기록인 오늘, 기본 슬롯, 기준 상황). 지어낸 기록을 기준으로 삼지 않는다.
     - 자유롭게 비교하게 하려면 `tabs`, 순서 있는 이야기(오늘→내일)면 단계형으로 쓴다.
   - **사진이 증거 → `photos`**
     - `focus`로 한 장을 키운다.
     - `zones`는 원문이 위치를 말한 경우에만 쓴다(예: "왼쪽 가장자리").
     - 100% 크롭은 `detail`로 넣는다.
     - 위치에 관한 규칙은 사진 없이 도식 프레임으로 그린다.
   - **데이터 없는 인과 문장, 참고표, 실행할 일 → 정적 블록** `text`·`table`·`compare`·`checklist`·`note`
     - 원문이 설명하지 않은 메커니즘(파형, 측광 도식, 스타일 시뮬레이션)은 그리지 않는다.
4. **정적/동적을 장면마다 정한다.**
   - 상태 변화가 의미를 가질 때만 비트를 쓴다: 분할, 세분, 범위가 값으로 줄어듦, 기록 간 차이, 정확한 값 읽기.
   - 마지막 상태 하나로 다 설명되면 상태 1개(정적 그림)로 쓴다.
   - 체크리스트, 카메라에 그대로 옮길 참고표, 문장형 장단점 비교는 정적으로 둔다. 보통 문서의 1/3쯤은 정적이다.
5. **비트를 쓴다.**
   - 무대당 2~6개를 쓴다. 각 비트는 정확히 한 가지만 바꾸고, 첫 비트는 전체를 보여 준다.
   - `say`는 원문 문장을 그대로 쓰거나, 원문 문장을 그 자리(→, =, 마침표)에서 잘라 쓴다. 원문 조각을 이어 붙이는 것까지만 허용한다.
   - 쓸 문장이 없으면 `say`를 비운다. 렌더러가 원문 값으로 데이터 줄을 만든다. 문장을 지어내지 않는다.
   - 장면 `message`는 마지막에 결론으로 붙으므로 비트에서 반복하지 않는다.
6. **다양성을 점검한다.**
   - 같은 무대 종류가 이어 쓰기 없이 세 장면 연속이면, 가운데 장면을 다시 고른다. 같은 종류를 쓰더라도 축·데이터가 달라야 한다.
   - 정적 참고 장면은 세 장면까지 이어져도 된다.
   - "제목 + 표 + 사진 + 메모"로 읽히는 장면이 남아 있지 않은지 확인한다.
7. **사진을 준비한다.**
   - 사진은 `src`·`photo`에 파일 경로로 쓴다. base64와 HTML은 쓰지 않는다.
   - 원본이 500KB를 넘거나 RAW·HEIC면 줄여서 `.showtell/assets/`에 둔다:
     `mkdir -p "${CLAUDE_PROJECT_DIR}/.showtell/assets" && sips -Z 1000 -s format jpeg "<원본>" --out "${CLAUDE_PROJECT_DIR}/.showtell/assets/<이름>.jpg"`
   - 위치 영역(zone)을 쓰기 전에 Read 도구로 사진을 직접 본다.
8. **명세를 작성한다.** Write 도구로 `${CLAUDE_PROJECT_DIR}/.showtell/<영문-케밥-이름>.json`에 쓴다(절대 경로). 전체 형식은 [reference.md](reference.md), 모든 무대를 쓰는 예시는 [example.json](example.json)에 있다.
9. **렌더링한다.**

   ```bash
   node ${CLAUDE_SKILL_DIR}/render.mjs "${CLAUDE_PROJECT_DIR}/.showtell/<이름>.json"
   ```

   - 오류는 메시지의 경로대로 고친다(예: `spec.scenes[1].stage.states[3].groups: 합 600 ≠ total 601`). 경고(큰 사진, 눈금 겹침)도 가능하면 고친다.
   - 기존 결과물은 덮어쓰지 않고 번호가 붙은 새 파일이 생긴다.
10. **안내한다.** 출력된 파일 경로와 함께 핵심 결론을 텍스트로 2~4줄 요약한다. 사용자가 파일을 열지 않아도 답을 알 수 있어야 한다.

## 4. 충실성 규칙 (반드시 지킨다)

- 원문의 **사실, 수치, 단위, 조건을 바꾸지 않는다**. 반올림·환산·요약으로 값이 달라지면 안 된다.
- **계산한 숫자를 보여 주지 않는다**(차이, 나머지, 비율, 합계, 행 개수, 구간별 프레임 수). 화면의 모든 숫자는 원문에 있어야 한다.
- `units`의 분할은 전체 합과 같아야 한다(렌더러가 검사한다).
  - `"rest"`는 "전체 − 원문에 적힌 부분"이 정확히 정해질 때만 쓰고, 그 개수는 표시되지 않는다.
  - "그 외 소수" 같은 모호한 나머지에는 쓰지 않는다. 그런 데이터는 `track` 막대로 그린다.
- 원문이 교차표를 주지 않으면 두 분할 사이에 점이 이동하는 것처럼 보이게 하지 않는다. `of`·`from`은 원문이 포함 관계를 말할 때만 쓴다.
- 조절 요소(탭·슬라이더·스크럽)는 **원문의 행·값·구간만** 오간다. 사이 값을 보간하지 않는다. 원문에 없는 값을 "기록 없음" 같은 말로 채우지 않는다. 눈금도 원문 값만 쓴다.
- 사진과 프레임은 캡션에 적힌 값·구간에만 놓는다.
- 범위는 원문이 범위로 말할 때만 쓴다. "1/125 (움직이면 1/160)"은 1/125 핀이고, 괄호는 라벨이다.
- 오늘의 데이터 분포 위에 내일의 권장값을 겹쳐 그리지 않는다. 예: 연사 분포 위에 "포즈당 3~5장"을 그리지 않는다.
- 쉼표가 있는 원문 값("1,488", "5,507 → 6,109")은 문자열로 쓴다. 정적 `table` 셀의 숫자에는 자릿수 쉼표가 붙으므로 ISO·연도·코드처럼 쉼표가 없어야 하는 값은 표에서 문자열로 쓴다.
- 원문 값에 `**`나 백틱이 있으면(수식, 코드) 서식으로 바뀌지 않게 백틱으로 감싼다. 예: `` `2**10` ``
- 불확실성 표시는 하나도 빠뜨리지 않는다. 해당 값에 `uncertain`을 붙이거나 `note`(`uncertain`)로 남긴다. "약 2배" 같은 근사치는 막대 길이로 그리지 않는다.
- 다른 문서의 값을 가져와 채우지 않는다. 원문에 없는 칸은 `"—"`로 쓴다.
- 사용자의 기존 파일을 덮어쓰지 않는다. 결과물과 사진 사본은 `.showtell/` 안에만 만든다.
